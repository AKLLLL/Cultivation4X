# 宗门弟子自主行为系统 V1 实施方案

> 状态：待审批（计划阶段，未动任何代码）
> 依据：《宗门弟子自主行为系统》思路文档 V0.1 + 多轮设计访谈共识 + 用户最终修订
> 编码：UTF-8

---

## 一、目标与范围

实现 V0.1 文档定义的 V1 闭环：

**读取状态 → 生成 Goal → Utility 选 Action → 通过 Mission 执行一段时间 → 生成经历。**

- 激活对象：`hasGeneratedProfile` 的建宗弟子（3 名 Founder），`founding.completed == true` 后生效。
- 玩家直接命令 = 既有 Mission 派遣；NPC 非 `Idle` 时自主层不介入。
- **不做**：月度计划 UI、身份/权限制度系统、月度时间模型、地图自主探索、EventContext 临时修正、AI 调试 UI 面板、存档字段变更、疲劳/心境数值。

### 第一轮：范围与总体路线

## 三、架构总览

```
TimeManager.EndDay
  → NPCManager.OnDayPassed（空闲弟子每日修炼）
  → MissionManager.OnDayPassed（自主 Mission 推进/终局/NPC Recover）
  → ExternalThreatRules → EventManager.ProcessDay
  → BuildSettlement → AutoSave
  → OnDaySettlementReady
       → DiscipleDecisionManager.ProcessSettledDay(day)
           1. Settlement Growth Check（结算成长检查，归属成长系统）：
              对 Idle 存活自主弟子调 TryBreakthrough()（方法内自决阈值与成败记录）
           2. DiscipleMissionBridge：扫描终局的 disciple_ai_* Mission
              → social 完成：调既有 NPCManager.AddRelationship（扩展后自动写双方记录）
              → 标记该弟子 LastActionEndedDay（冷却 1 周期）
           3. DiscipleAIEvaluator：对每个空闲自主弟子
              → 生成 Goal（条件 + 加权 + 滞后）
              → 过滤 Action（身份 / 零成本 / 设施占用 / 无节点 / 模板存在）
              → Utility 评分 → 选最高
           4. 选中则 ExperienceGenerator 写“因{reason}，决定{action}”
              → DiscipleMissionBridge 启动 Mission → AutoSave
```

## 六、既有代码修改（3 处，全部经用户确认）

### 6.1 `NPCRuntime.TryBreakthrough()`：突破失败补记

在“已消耗修为且随机失败”分支 `return false` 前，方法内部补：

```csharp
Character.AddLifeRecord(
    TimeManager.Instance == null ? 0 : TimeManager.Instance.CurrentDay,
    "Breakthrough", $"突破失败，修为损耗 {need}");
```

- 签名不变、对外行为不变（只在原失败路径多一条 LifeRecord，属既有 `CharacterState.lifeRecords` 结构）。
- 成功路径沿用既有“突破至…”记录，不动。
- 影响面：`TryBreakthrough` 调用方仅测试与新增自主层；无存档结构变化。

### 6.2 `NPCManager.AddRelationship()`：扩展既有关系入口（不新建 RelationshipSystem）

原方法改为带可选文本参数的单一入口（既有 3 参调用源码兼容）：

```csharp
public bool AddRelationship(string sourceId, string targetId, RelationshipTag tag,
    string sourceRecordText = null, string targetRecordText = null)
{
    // 原有逻辑不变：校验双方存在、sourceId != targetId、重复关系拒绝
    // 关系写入成功后：
    //   1. source.Character.AddLifeRecord(day, "Relationship",
    //        sourceRecordText ?? 默认文本"与{target}结为{tag名}");
    //   2. target.Character.AddLifeRecord(day, "Relationship",
    //        targetRecordText ?? 默认文本"与{source}结为{tag名}");
    //   3. 双方各一条，满足第五轮 Q2；未来外交/师徒/仇敌复用同一入口
}
```

- tag 显示名映射（私有 helper）：Friend→好友、MasterApprentice→师徒、Rival→仇敌、LifeSaver→救命恩人。
- 新增兜底方法（无目标可建时写源方关系结果记录）：
  ```csharp
  public void RecordRelationshipOutcome(string characterId, string text)
  ```
  社交 Mission 终局找不到目标时，`DiscipleMissionBridge` 调用它写“独自静思，心境渐平”；所有 Relationship 类记录仍收敛在 NPCManager。
- **行为变化**：`EventManager` 的 AddRelationship 事件效果现在也会给双方留下 Relationship LifeRecord（既有调用 3 参，走默认文本）。这是本次扩展的预期收益，非回归。
- 受影响调用方：`EventManager.ApplyEffect`（3 参，源码兼容）、新增社交桥（5 参/兜底）。

### 6.3 `MissionData.isPlayerAssignable` + `MissionManager.IsMissionVisible`：AI 模板隐藏

- `MissionData.cs` 新增字段：
  ```csharp
  public bool isPlayerAssignable = true;
  ```
  默认 `true`：所有既有 JSON 不写该字段仍可玩家派遣；AI 模板显式写 `false`。
- `MissionManager.IsMissionVisible()` 开头加：
  ```csharp
  if (!data.isPlayerAssignable) return false;
  ```
  效果：`GetVisibleMissions()`（MissionPanel 列表）、`CanTriggerMission`/`TriggerMission`（玩家派遣）、`RefreshDailyCandidates` 全部自动排除 AI 模板。
- AI 桥接层**不调用** `IsMissionVisible`（按第二轮 Q7），因此 AI 仍可启动这些模板；玩家侧不会被 4 个 AI 模板污染。
- `RegisterMapMissionTemplates` 动态构造的 MissionData 走字段初始化默认 `true`，不受影响。

## 八、关键算法约定

### 8.1 候选过滤规则（开跑前全部满足）

1. `founding.completed == true`；
2. 弟子存活、`State == Idle`、`CurrentMission == null`、`hasGeneratedProfile`；
3. Action 的 `identityIds` 含该弟子当前身份；
4. 目标 Mission 模板存在、无 `nodes`、`goldCost == 0` 且无 `itemCosts`、非 story/worldEvent/generatedByMap（**不要求 isPlayerAssignable==true，AI 模板本就 false**）；
5. 设施类 Action 需 `GetFacilityLevel(requiredFacility) >= requiredFacilityLevel`；
6. 同一设施不被其他进行中 Mission 占用；
7. 不使用玩家面板的 `IsMissionVisible`（声望/排名/可派遣性是玩家侧门槛，不是 NPC 能力门槛）。

### 8.2 评分公式

```
ActionScore = baseline + Σ weight × curve(input)
```

- 输入先归一化 0–1，再走线性分段响应曲线（默认恒等曲线）。
- 允许负权重。
- 同分取 `actionId` 字典序最小；无随机扰动。
- 决策原因 = 最高正贡献项，映射为可读标签（Goal→Goal 名，Trait→特质名，CultivationRatio→“瓶颈临近”，AptitudeRank→“天资”，WarehouseScarcity→“资源匮乏”）。

### 8.3 输入词表（词表外 V1 不实现）

- **Goal 条件**：`Always`、`HasTrait`、`MissingTrait`、`RealmAtLeast`、`RealmAtMost`、`HealthIs`、`CultivationRatioBelow`、`WarehouseItemBelow`、`RelationshipCountBelow`。
- **评分输入**：`GoalIntensity.<goalId>`、`Trait.<traitId>`（有=1 无=0）、`RealmIndex`、`CultivationRatio`、`AptitudeRank`、`HealthScore`、`FacilityAvailable.<facility>`、`WarehouseScarcity.<itemId>`、`IdentityFreedom`、`Interest.<tag>`（V1 恒 0，字段预留）、`EventContext.<id>`（V1 恒 0，字段预留）。

### 8.4 Goal 生成

- 强度 = clamp(baseIntensity + Σ weight × curve(input), 0, 10)。
- 滞后：`intensity = max(新值, 旧值 × 0.5)`。
- 激活阈值 3；取 top 3。

### 8.5 结算成长检查（Settlement Growth Check）

- 每日结算后触发，对 Idle 存活自主弟子调用 `TryBreakthrough()`。
- AI 层零知识：不检查阈值、不看结果、不写记录；阈值判断与成功/失败记录都在成长系统内部闭合。

### 8.6 社交关系

- Mission 终局时，按 `characterId` 升序取第一个“非自己、存活、双方无任何关系记录”的弟子。
- 找到：`NPCManager.AddRelationship(sourceId, targetId, Friend, "与{target}结为好友，心境渐安", "与{source}结为好友")`。
- 找不到：`NPCManager.RecordRelationshipOutcome(sourceId, "独自静思，心境渐平")`。

### 8.7 冷却

- `LastActionEndedDay == 当日` 的弟子本周期不参与新决策，给玩家一整天派遣窗口。
